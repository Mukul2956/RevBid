## A. Everything in Docker (fastest)

```bash
docker compose up --build          # web http://localhost:8080 · API http://localhost:8100/docs
docker compose --profile observability up --build -d   # + Prometheus :9090 · Grafana :3000
```

The API container runs migrations and seeds demo data on start (`RUN_MIGRATIONS`/`RUN_SEED`), and
`DEMO_MODE=true` keeps a few auctions open. The `web` container (nginx) serves the SPA and proxies `/api`
and `/ws`, standing in for Vercel.

Grafana (anonymous viewer enabled; admin/admin) provisions the **"Auction platform: overview"** dashboard
automatically; Prometheus loads the alert rules from `deploy/prometheus/alerts.yml`.

**Demo accounts** (created by the seed):

| Role | E-mail | Password |
|---|---|---|
| Administrator | `admin@bikeauction.dev` | `Admin@12345` |
| Bidder | `buyer1@bikeauction.dev` | `Buyer@12345` |
| Bidder | `buyer2@bikeauction.dev` | `Buyer@12345` |

(Override with `SEED_ADMIN_PASSWORD` / `SEED_BUYER_PASSWORD`; the login page shows them when
`VITE_SHOW_DEMO_CREDENTIALS` isn't `false`.)

## B. Local development (hot reload)

```bash
# 1. data services (Postgres on :5433, Redis on :6380: non-default ports so they don't clash with a local install)
docker compose up -d db redis

# 2. backend
cd backend
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
python -m alembic upgrade head
python -m scripts.seed
DEMO_MODE=true python -m uvicorn app.main:create_app --factory --reload --port 8100
#                              Windows PowerShell: $env:DEMO_MODE="true"; python -m uvicorn ...

# 3. frontend (another terminal)
cd frontend
npm ci            # if NODE_ENV=production is set in your shell: npm ci --include=dev
npm run dev       # http://localhost:5173  (proxies /api to :8100; the WebSocket connects to :8100 directly)
```

`make dev-api` / `make dev-web` wrap the same steps on macOS/Linux/WSL.

**Run the tests**

```bash
cd backend  && pytest --cov=app                  # needs `docker compose up -d db redis`; unit tests alone need nothing
cd frontend && npm run lint && npm run typecheck && npm test
cd frontend && npx playwright install chromium && npm run e2e   # needs API on :8100 + `npm run dev`
```

> E2E logs in dozens of times from one IP. Start the API with
> `RATE_LIMIT_LOGIN_PER_MIN=1000 RATE_LIMIT_REGISTER_PER_MIN=1000 DEMO_MODE=false` for E2E runs (the limiter
> itself is covered by its own tests).

**Load test:** see [`loadtest/README.md`](../loadtest/README.md).

## C. Production: Render + Vercel

Architecture: the browser talks to **Vercel**, which serves the SPA and **rewrites `/api/*` to Render**
(so the refresh cookie is same-origin). The **WebSocket connects directly to Render** (Vercel can't proxy
WebSockets).

### 1. Push the repository to GitHub

### 2. Render: API, Postgres, Redis

1. Render dashboard → **New → Blueprint** → select the repo. It reads [`render.yaml`](../render.yaml) and creates
   `revbid-api` (Docker web service from `backend/`), `revbid-db` (Postgres) and `revbid-redis` (Key Value).
2. When prompted, fill the `sync: false` variables. Leave `CORS_ORIGINS` / `WS_ALLOWED_ORIGINS` for step 4:
   - `SEED_ADMIN_PASSWORD`, `SEED_BUYER_PASSWORD`: the demo-account passwords you will publish
   - `SENTRY_DSN`: optional
3. `JWT_SECRET` and `METRICS_TOKEN` are generated by Render. The app **refuses to start in production** with a
   weak secret or without `COOKIE_SECURE=true`, so a misconfiguration fails loudly at deploy time.
4. The container's entrypoint runs `alembic upgrade head`, then (first deploy) `python -m scripts.seed`.
5. Note the service URL, e.g. `https://revbid-api.onrender.com`. Check `…/readyz` → `{"status":"ready"}`.

> **Free tier:** the web service sleeps after ~15 minutes idle, and free Postgres may be time-limited. Check Render's
> current terms. If the free database expires, use a permanent free Postgres (e.g. Neon) and set `DATABASE_URL`
> (the app accepts `postgres://`, `postgresql://` and `?sslmode=require`).

### 3. Vercel: frontend

1. Point the Vercel config at your API host (one command, or edit by hand):
   ```bash
   make vercel-config API_HOST=revbid-api.onrender.com      # replaces __API_HOST__ in frontend/vercel.json
   ```
   This sets the `/api/*` rewrite destination and the CSP `connect-src` entry for the WebSocket. Commit it.
2. Vercel → **Add New Project** → import the repo → **Root Directory: `frontend`** (framework is auto-detected as Vite).
3. Environment variables (Project → Settings → Environment Variables):

   | Name | Value |
   |---|---|
   | `VITE_WS_URL` | `wss://revbid-api.onrender.com/ws` |
   | `VITE_SHOW_DEMO_CREDENTIALS` | `true` (shows the demo accounts on the login page) |

4. Deploy. Note the URL, e.g. `https://revbid.vercel.app`.

### 4. Tell the API about the frontend origin

In Render → `revbid-api` → Environment, set (JSON arrays):

```
CORS_ORIGINS        ["https://revbid.vercel.app"]
WS_ALLOWED_ORIGINS  ["https://revbid.vercel.app"]
```

The service redeploys. (`WS_ALLOWED_ORIGINS` is what stops other websites from opening sockets as your users.)

### 5. Keep the free API warm (optional but recommended)

GitHub → repo → Settings → *Secrets and variables → Actions → Variables* → add `API_URL =
https://revbid-api.onrender.com`. The `keepalive.yml` workflow then pings `/healthz` every 10 minutes. (Auction
correctness doesn't depend on this; it just avoids cold starts for reviewers.)

## Configuration reference

All configuration is environment variables (12-factor). Defaults are safe for local development.

| Variable | Default | Notes |
|---|---|---|
| `ENV` | `local` | `production` enables strict validation (secret length, secure cookies) and JSON logs |
| `DATABASE_URL` | local compose | `postgres://`, `postgresql://` and `?sslmode=` are normalised to asyncpg |
| `REDIS_URL` | local compose | pub/sub + rate limits |
| `JWT_SECRET` | dev placeholder | **required (≥ 32 chars) in production** |
| `COOKIE_SECURE` / `COOKIE_SAMESITE` | `false` / `lax` | production needs `true`; `none` requires secure |
| `CORS_ORIGINS`, `WS_ALLOWED_ORIGINS` | `["http://localhost:5173"]` | JSON arrays |
| `ACCESS_TOKEN_TTL_MINUTES` / `REFRESH_TOKEN_TTL_DAYS` | `15` / `7` | |
| `RATE_LIMIT_ENABLED`, `RATE_LIMIT_LOGIN_PER_MIN`, `RATE_LIMIT_REGISTER_PER_MIN`, `RATE_LIMIT_REFRESH_PER_MIN`, `RATE_LIMIT_BIDS_PER_10S` | on, `10`, `5`, `60`, `20` | per client IP (login also per account); bids per user |
| `MAX_REQUEST_BODY_BYTES` | `262144` | larger bodies get `413` before parsing |
| `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` | `10`, `10` | write pool (health-checked connections). Mind your Postgres connection limit |
| `DB_READ_POOL_SIZE`, `DB_READ_MAX_OVERFLOW` | `10`, `10` | separate pool for read-only endpoints |
| `DB_READ_AUTOCOMMIT`, `DB_READ_PRE_PING` | `true`, `false` | the fast read path (no `BEGIN`/ping). Flip to `false`/`true` to trade speed for connection health checks |
| `KEEPALIVE_TIMEOUT` | `75` | uvicorn keep-alive seconds; must exceed the load balancer's idle timeout |
| `FORWARDED_ALLOW_IPS` | `*` | trusted proxy IPs for `X-Forwarded-For`; tighten where the host publishes its proxy range |
| `MAX_BID_AMOUNT` | `1000000000` | paise (₹1 crore) |
| `DEFAULT_SNIPE_WINDOW_S` / `_EXTENSION_S` / `DEFAULT_MAX_EXTENSION_S` | `120` / `120` / `1800` | per-auction overrides exist |
| `RUN_SCHEDULER`, `SCHEDULER_INTERVAL_S` | `true`, `1.0` | set false to run the loop elsewhere |
| `DEMO_MODE`, `DEMO_MIN_OPEN_AUCTIONS` | `false`, `4` | keeps auctions open for reviewers |
| `WS_MAX_CONNECTIONS_PER_USER`, `WS_SEND_QUEUE_SIZE`, `WS_MESSAGES_PER_SECOND`, `WS_BURST` | `10`, `100`, `20`, `40` | realtime protection |
| `METRICS_TOKEN` | unset | if set, `/metrics` needs `Authorization: Bearer <token>` |
| `SENTRY_DSN` | unset | error tracking |
| `RUN_MIGRATIONS`, `RUN_SEED` | `true`, `false` | container entrypoint behaviour |
| `SEED_ADMIN_PASSWORD`, `SEED_BUYER_PASSWORD` | demo defaults | used by the seed script |

Frontend build-time (`VITE_*`, public, baked into the bundle): `VITE_WS_URL`, `VITE_SHOW_DEMO_CREDENTIALS`,
`VITE_DEMO_BUYER_PASSWORD`, `VITE_DEMO_ADMIN_PASSWORD`.

## Post-deploy checklist

- [ ] `GET /readyz` → `ready` (database and Redis `ok`)
- [ ] Open the Vercel URL → live auctions are listed with photos
- [ ] Log in as a bidder → the auction page shows **"Live updates on"** (the WebSocket works)
- [ ] Open the same auction in a second private window as the other bidder → bids appear instantly in both
- [ ] Browser DevTools → Application → Cookies: `refresh_token` is `HttpOnly; Secure`, path `/api/v1/auth`
- [ ] Reload the page while logged in → the session is restored (refresh cookie works through the rewrite)
- [ ] Log in as admin → Admin → **System**: database/Redis healthy, scheduler ticking (< 5 s ago)
- [ ] `curl -H "Authorization: Bearer <METRICS_TOKEN>" https://…/metrics` returns Prometheus text; without the token → 401
- [ ] Log in with a wrong password 11× quickly → `429` with `Retry-After`

## Operations

- **Logs** are JSON on stdout (Render → Logs). Filter by `request_id` (also returned in the `X-Request-ID` header and in
  every error body) to follow one request end to end. Useful events: `bid_accepted`, `bid_rejected`, `auction_started`,
  `auction_ended` (with `lag_s`), `ws_dropped`, `scheduler_tick_failed`, `refresh_token_reuse_detected`.
- **Metrics:** scrape `/metrics`. Locally the observability profile gives you Prometheus + Grafana + alert rules.
  In production on a free tier, use the in-app **Admin → System** page, or point a hosted Prometheus/Grafana Cloud
  agent at `/metrics` using the bearer token.
- **Deploys:** pushing to `main` redeploys both services (Render and Vercel auto-deploy). Migrations run on container start.
- **Rollback:** Render → *Rollbacks* (or redeploy a previous commit); Vercel → *Deployments → Promote*. Migrations are
  additive. For a destructive change, ship it expand/contract in two releases.
- **Graceful shutdown:** the container uses `exec` so uvicorn is PID 1 and handles SIGTERM; every shutdown step is time-boxed.
- **Secrets:** rotate `JWT_SECRET` to invalidate all sessions; users simply log in again.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Page loads but "Reconnecting…" forever | `VITE_WS_URL` wrong, or Origin not allowed | Set `VITE_WS_URL=wss://<api-host>/ws` and `WS_ALLOWED_ORIGINS` to the exact Vercel origin; redeploy the frontend |
| Logged out on every refresh | Cookie not set/sent | Confirm `/api/*` goes through the Vercel rewrite (same origin) and `COOKIE_SECURE=true` over HTTPS; check `__API_HOST__` was replaced |
| `502`/timeouts on the first request | Free instance cold start (30-60 s) | Retry; enable the keep-alive workflow |
| API won't start: *JWT_SECRET must be set…* | Production safety check | Provide a ≥ 32-char secret and `COOKIE_SECURE=true` |
| `429` during demos | Rate limit | Wait the `Retry-After`; tune `RATE_LIMIT_*` |
| Auctions end late after the service wakes | Expected on free tier | Bids were still refused on time; the scheduler catches up on its first tick |
| `asyncpg … ssl` errors on an external DB | Missing SSL param | Use `?sslmode=require` (normalised automatically) |
| Local: `password authentication failed` | A different Postgres is bound to the port | The compose file uses host ports **5433/6380** to avoid clashes; check `DATABASE_URL` |
| `npm ci` skips dev tools | `NODE_ENV=production` in your shell | `npm ci --include=dev` |
